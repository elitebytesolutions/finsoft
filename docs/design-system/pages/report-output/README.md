# Report output

| | |
|---|---|
| **Route** | `/reports/:id` |
| **Archetype** | H — Report |
| **Module / permission** | Reports · `Reports` |
| **Prototype source** | `ui-prototype/src/reports-pages.tsx` (`ReportOutput`), `src/report-engine.ts` |
| **Posts to the ledger** | no |

## 1. Purpose

Run one report and read its result. Every report in the product — built-in or from the studio —
renders here, so the formatting rules are enforced in one place.

## 2. Anatomy

```
Breadcrumbs   Reports > <category> > <report name>
PageHead      report name (h1) · description · [Filters] [Export v] [Print] [Save as template]
FilterStrip   the report's parameters: date range, branch, party, class, grouping
AppliedChips  removable, + Clear all
ReportHeader  company · period · filters applied · accounting method · generated at · generated by
DataTable     the output, with group subtotals and a grand total
Footer        row count · totals · pager · rows per page
```

## 3. Components

`PageHead` · `FilterBar` · `FilterChip` · `ReportHeader` (page-local, but identical across reports)
· `DataTable` (grouped, totalled) · `ExportMenu` · `PrintDocument` · `EmptyState`.

## 4. Formatting rules (enforced here for every report)

- Numeric columns right-aligned and tabular; money with 2 decimals and no abbreviation.
- Group subtotal rows: top border, 700 weight. Grand total: tinted row, 700, at the foot.
- Negative figures in brackets with `--money-negative`.
- Em dash for a true zero in a ledger-style report; `0.00` in a totals row.
- A column that the user's role may not see is **absent**, and the header states that columns were
  omitted for permissions — a blank column invites a support ticket.

## 5. The report header block — mandatory

Every output and every export carries: tenant name, report name, period or as-at date, every filter
applied, the accounting basis where relevant, generated-at timestamp with timezone, and the user.
A report without provenance is not a report; it is a screenshot.

## 6. Actions

| Action | Kind | Permission | Result |
|---|---|---|---|
| Change filters | control | `Reports` | Re-runs; URL state so the run is shareable |
| Export | secondary split | `Reports` | PDF / XLSX / CSV with identical figures and the same header block |
| Print | secondary | `Reports` | `PrintDocument` with repeating table headers |
| Save as template | ghost | `Reports` | Stores the current filter set |

## 7. Financial rules

- Figures come from the server. The browser sorts and paginates; it never sums, filters money, or
  re-derives a total.
- Footer totals are the **whole result set**, not the visible page, and are labelled accordingly;
  page totals, when shown, say "this page".
- Draft documents are excluded unless the report explicitly includes them, and the header says which.

## 8. States

Report not found → "Report not found" with a route back to the catalogue.
No rows for the filters → empty state naming the filters, not a blank table.
Async run in progress → a progress state with a collection point.
Export failure → error with a retry that does not re-run the query.

## 9. Responsive · 10. Accessibility

`md` the filter strip becomes a Filters sheet · `sm`+ the table scrolls with the first column sticky
· `xs` the output is offered as a download rather than a cramped table.
`<caption>` contains the full header block text so screen readers get provenance before figures;
group subtotal rows are `<th scope="row">`.
